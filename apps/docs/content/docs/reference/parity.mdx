## What this catalog means

This catalog is generated from the same structured provenance model used by component fidelity summaries. It is an index of **documented evidence and fidelity claims**, not a percentage score and not a claim that every pixel or internal Compose mechanism is reproduced literally on the web.

## How to read it

Every entry separates provenance into `spec`, `compose`, `web`, and `adaptation` evidence. Material overview, guideline, and specification links are recorded independently when they are available; an Android Developers reference is treated as Compose evidence rather than silently promoted to Material-site guidance.

Visual, behavior, and semantics fidelity are independent fields. `aligned`, `adapted`, `partial`, and `not-applicable` are descriptive states, not percentages. Intentional adaptations and known gaps are separate queryable lists rather than being folded into an ambiguous parity sentence.

## Source-of-truth boundary

This page contains no second component inventory. `allComponentDocs` remains the documented component inventory, while `allComponentProvenance` resolves that inventory into the structured fidelity contract consumed by this catalog and the MDX fidelity renderer. Sparse overrides enrich individual entries without copying the full inventory.

Canonical dimensions, typography, color roles, motion values, and component tokens continue to come from the generated token graph and audited component runtime rather than this documentation surface.

## Current exclusions

The catalog covers component guides that are intentionally published today. It does not promote `BottomSheetScaffold`, adaptive pane policy, window-size classes, or navigation-mode switching into this component registry while the dedicated layout/adaptive subsystem is evolving separately.

Foundations such as color, typography, and theming also remain outside the component count because they have their own runtime contracts and documentation sections.
