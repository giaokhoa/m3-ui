Use these guides when the task spans more than one Material component or belongs to the surrounding application rather than a single component family.

- [Forms and validation](/docs/develop/forms) covers native form ownership, validation, controlled and uncontrolled values, and composition across fields and selection controls.
- [Adaptive layout and navigation](/docs/develop/layout) covers window adaptive information, scaffolds, panes, and application-level navigation policy.
- [Web accessibility](/docs/develop/accessibility) covers the browser semantics, focus, keyboard, naming, live-region, and reduced-motion contracts shared across the library.

For visual system values and runtime theme projection, use [Foundations](/docs/foundations) and [Theming](/docs/foundations/theming). Individual component anatomy, variants, and component-local behavior remain in [Components](/docs/components).

## Ownership boundary

These pages explain how public `m3-ui` APIs compose in a web application. They do not create a second design system or docs-only runtime: Material owns design intent, the web platform and React Aria own browser semantics, and application code owns product state, routing, validation policy, and content relationships outside component contracts.
