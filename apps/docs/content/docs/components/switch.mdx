Switches represent an immediate on/off setting. Activating the control changes the setting directly; use a checkbox instead when the user is selecting options to submit or confirm later.

[Material 3 switch](https://m3.material.io/components/switch/overview)

</ComponentPreview>

```tsx
import { Switch } from '@m3-ui/ui';

<Switch defaultSelected>Notifications</Switch>
```

## When to use

Use a switch for settings whose result takes effect as soon as the state changes, such as enabling automatic updates. Use checkboxes for independent form choices and toggle buttons for persistent button-like modes/actions.

## Selection state

`Switch` inherits controlled and uncontrolled React Aria selection props. Application state is the source of truth; do not style the track or thumb directly to simulate selection.

```tsx
<Switch isSelected={enabled} onChange={setEnabled}>
  Automatic updates
</Switch>
```

## Thumb content

`thumbContent` renders decorative/supporting content inside the Material thumb while the switch remains the only semantic control.

```tsx
<Switch thumbContent={<CheckIcon />} defaultSelected>
  Enabled
</Switch>
```

Do not place a second interactive control inside the thumb.

## Behavior and states

React Aria supplies switch semantics, keyboard/pointer behavior, disabled state, form participation, and controlled/uncontrolled selection. Material tokens own track/thumb geometry, color, ripple/state layers, and minimum interaction size.

The global `ThemeProvider` ripple-focus configuration can change the visual focus treatment without changing the underlying switch semantics.

## Accessibility

Visible children should identify the setting. A control-only switch needs an explicit accessible name. Keep the label stable as state changes; the switch role communicates on/off state.

Do not rely only on thumb color or icon to communicate state. Disabled switches should be used only when the setting is genuinely unavailable.
