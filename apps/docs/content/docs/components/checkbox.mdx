Checkboxes represent independent binary choices and can also display an indeterminate state when a parent choice summarizes mixed child selections.

[Material 3 checkbox](https://m3.material.io/components/checkbox/overview)

<ComponentPreview>

</ComponentPreview>

```tsx
import { Checkbox } from '@m3-ui/ui';

<Checkbox name="remember" defaultSelected>
  Remember this device
</Checkbox>
```

## When to use

Use checkboxes when each option can be selected independently. Use radio buttons when exactly one option in a set is allowed, and use a switch for an immediate on/off setting where changing the state takes effect directly.

## States

The public component distinguishes unchecked, checked, indeterminate, and disabled states.

```tsx
<Checkbox>Unchecked</Checkbox>
<Checkbox defaultSelected>Checked</Checkbox>
<Checkbox isIndeterminate>Partially selected</Checkbox>
<Checkbox isDisabled>Disabled</Checkbox>
```

`isIndeterminate` communicates mixed/partial selection. It is not a substitute for the application's actual selected value; application logic remains responsible for resolving parent/child selection state.

## Behavior and form semantics

React Aria owns checkbox semantics, keyboard activation, controlled/uncontrolled selection, focus-visible behavior, and native form-related props such as `name` and `value`.

Visible children act as the label. Material tokens own the box, check/indeterminate mark, state layers, ripple, colors, and minimum interaction geometry.

## Accessibility

Prefer a visible label. If a checkbox intentionally has no visible label, provide an accessible name through the inherited React Aria props.

Do not use color or the checkmark alone to communicate a validation message; pair invalid form state with accessible text and the surrounding field/form relationships described in the Forms guide.
