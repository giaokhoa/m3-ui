Tabs organize peer destinations or content categories within a shared context. `Tabs` renders the Material tab-list surface; the application owns the selected content, route, or panel relationship unless it composes those semantics separately.

```tsx
import { Tabs } from '@m3-ui/ui';

<Tabs

  defaultSelectedKey="overview"

    { id: 'overview', label: 'Overview' },
    { id: 'activity', label: 'Activity' },
    { id: 'settings', label: 'Settings' },
  ]}
/>
```

## When to use

Use tabs for a small set of peer views that users may switch between without leaving the broader context. Do not use tabs as a substitute for global destination navigation or for unrelated actions.

## Selection and content ownership

Use `selectedKey` with `onSelectionChange` when route/content state is controlled by the application, or `defaultSelectedKey` for uncontrolled tab-list state.

`Tabs` intentionally stops at the tab-list surface. It does not create hidden panels, routes, browser history, or URL state. If the selected key drives routing, keep that mapping in the router/application and connect any panel semantics explicitly.

## Primary and secondary variants

`variant="primary"` is the primary Material tab family; `variant="secondary"` uses the secondary indicator/geometry contract. Optional icons follow the public Material placement options.

`mode="fixed"` distributes the tab row according to the audited Material layout. `mode="scrollable"` keeps intrinsic tab widths and locally scrolls the selected tab into view. Reduced-motion preference disables smooth scrolling without changing selection.

## Behavior and accessibility

React Aria `Tabs`, `TabList`, and `Tab` own tab roles, roving focus, arrow-key behavior, disabled state, and automatic keyboard activation. Every tab list needs an accessible name.

Do not add custom arrow-key handlers or make tabs behave like generic buttons. When panels are composed by the application, preserve the corresponding tab/panel relationship rather than relying only on visual selection.
