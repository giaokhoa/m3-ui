Loading indicators use the Material 3 expressive morphing shape sequence to communicate loading or progress. Use the standard progress-indicator family when the product calls for conventional linear/circular progress instead.

```tsx
import { ContainedLoadingIndicator, LoadingIndicator } from '@m3-ui/ui';

<LoadingIndicator aria-label="Loading" />
<ContainedLoadingIndicator aria-label="Preparing workspace" />
<LoadingIndicator aria-label="Import progress" value={0.72} />
```

## When to use

Use the expressive loading indicator where the Material expressive loading affordance is appropriate. Do not use it as decorative looping animation unrelated to a process.

`LoadingIndicator` is uncontained; `ContainedLoadingIndicator` uses its audited Material container and indicator color roles rather than a docs-only wrapper.

## Indeterminate and determinate modes

Omit `value` for indeterminate loading. Provide a value for determinate progress. The public implementation safely maps determinate progress into the supported Material range while React Aria remains the semantic progress owner.

## Shape and motion

The renderer follows the audited Material/Compose shape sequence and motion timing. Internal Material Shapes code exists to draw the component and is not exposed as a general-purpose public shape API.

With `prefers-reduced-motion: reduce`, the visual freezes at a valid frame while the accessible progress state remains unchanged.

## Accessibility

React Aria `ProgressBar` owns the semantic progress contract. The SVG drawing is hidden from accessibility, so every standalone indicator needs `aria-label` or `aria-labelledby`.

Do not add a duplicate live region that announces every animation frame. If the application needs status text such as “Preparing workspace,” expose stable meaningful status separately.
