Pull to refresh requests new data when users drag downward from the top edge of scrollable content. The component owns Material gesture progress and indicator presentation; the application owns the refresh operation and decides when it is complete.

```tsx
import { PullToRefresh } from '@m3-ui/ui';

const [isRefreshing, setRefreshing] = useState(false);

<PullToRefresh
  isRefreshing={isRefreshing}
  onRefresh={() => {
    setRefreshing(true);
    refreshData();
  }}
>
  <Feed />
</PullToRefresh>
```

## When to use

Use pull to refresh when the surrounding product already uses a scrollable refresh pattern and a top-edge drag is discoverable in context. Always keep another reasonable refresh path where product/accessibility requirements call for one; a gesture should not become the only possible data-reload mechanism.

## Refresh lifecycle is application-owned

`onRefresh` is a request callback, not a hidden promise/network contract. Keep `isRefreshing` true while application work is active, then set it false when that work finishes or fails.

The component does not fetch data, choose retry policy, cancel requests, or infer completion from a timeout.

## Gesture arbitration

A downward pointer gesture is claimed only when the pull-to-refresh root and the originating nested scrollable are already at their top edge. Vertical scrolling therefore remains with nested/page content until the Material refresh gesture is actually eligible.

Crossing the threshold arms the request; releasing while armed calls `onRefresh` once. Releasing early returns to idle. `enabled={false}` disables the gesture without disabling the wrapped content.

## Indicator customization

The default indicator communicates pull/refresh presentation and exposes polite refresh status. A custom `indicator` receives the logical lifecycle/progress state but must not take ownership of the refresh operation itself.

## Accessibility

Do not require users to discover a pointer-only gesture to understand or operate critical refresh behavior. Keep the refreshing status stable enough to be announced meaningfully and avoid repeatedly toggling status during one request.

Wrapped controls retain their own semantics; the refresh wrapper should not turn the entire scroll surface into a button.

## Material fidelity and web adaptation

The interaction follows the audited Compose Material3 PullToRefresh contract: external refreshing state, a threshold request, and indicator progress. Browser pointer/nested-scroll inspection replaces Compose nested-scroll internals while application data lifecycle remains external.
