List items organize related content into Material rows. The same visual family can represent passive content, an action, one-of-many selection, or independent multiple selection; those browser contracts must remain distinct.

[Material 3 lists](https://m3.material.io/components/lists/overview)

```tsx
import { ListItem } from '@m3-ui/ui';

<ListItem supportingText="Last synced 2 minutes ago">
  Material library
</ListItem>
```

## When to use

Use list items for repeated rows with a shared content hierarchy. Do not turn every row into a button merely because it is clickable-looking; choose passive, action, or selection semantics from what activation actually means.

Use native links for navigation when browser link behavior is required rather than modeling document navigation as a button action.

## Anatomy and line count

`overline` and `supportingText` determine one-, two-, or three-line Material arrangements, with `lineCount` available when the public composition needs an explicit line family. `leading` and `trailing` are visual slots; they should not become hidden duplicate controls.

## Passive and action rows

A passive `ListItem` is content only. Supplying `onPress` opts into the React Aria-backed button path with hover, press, focus-visible, ripple, and disabled behavior.

```tsx
<ListItem onPress={openDetails} supportingText="View details">
  Release notes
</ListItem>
```

Do not nest independent interactive controls inside an action row in a way that creates invalid nested interaction.

## Single selection

`selectionMode="single"` exposes radio-item semantics. Related rows belong in `ListItemSelectionGroup`, which provides the group relationship and one-of-many keyboard/focus behavior.

Single selection is not an ordinary action button and not an independent checkbox.

## Multiple selection

`selectionMode="multiple"` exposes checkbox semantics and independent selected state. Multiple-selection rows do not use the single-selection roving-focus contract.

Keep each selected state application-controlled/uncontrolled through the documented public API instead of styling selected rows directly.

## Drag presentation

`isDragged` is a Material visual state only. It does not implement HTML drag-and-drop, pointer reordering, data transfer, or application sorting by itself.

## Accessibility

Choose the semantic mode that matches the row's real behavior. Keep leading/trailing decorative content from becoming duplicate accessible names, and use real links when navigation semantics are needed.

For selectable rows, preserve the radio vs checkbox distinction. For action rows, ensure the whole action has a clear accessible name and avoid nested interactive descendants.
