Time pickers let users choose a time of day with a Material clock dial, native numeric input, or the current expressive scroll presentation. `TimePicker`, `TimeInput`, and `TimeScroll` all use the same normalized `TimeOfDay` value, so applications can switch presentations without translating the selected time.

```tsx
import {
  TimeInput,
  TimePicker,
  TimeScroll,
  type TimeOfDay,
} from '@m3-ui/ui';

const [time, setTime] = useState<TimeOfDay>({ hour: 14, minute: 30 });

<TimePicker value={time} onChange={setTime} />
<TimeInput value={time} onChange={setTime} />
<TimeScroll value={time} onChange={setTime} />
```

## When to use

Use the dial when spatial clock selection supports the task, `TimeInput` when direct keyboard entry is more efficient, and `TimeScroll` when the current expressive vertical-wheel presentation fits the product flow. All three represent a time of day, not a timezone-aware instant or scheduling object.

A dialog, title, confirmation buttons, or a control that switches between dial/input/scroll modes remains application composition. The picker surfaces do not own product dialog lifecycle merely because Compose also provides dialog helpers around them.

## Shared time state

`TimeOfDay` always stores the **last valid** normalized 24-hour value: `hour` is `0..23` and `minute` is `0..59`. Twelve-hour presentation changes what users see and how AM/PM is selected; it does not change the application state model.

This lets an application render any of the three presentations against one controlled value. Switching from dial to input to scroll does not require a second conversion layer.

## Scroll selection

`TimeScroll` maps the current Material `TimeScroll` capability to two existing `ScrollField` controls rather than creating another generic scrolling engine. The hour and minute wheels therefore reuse the shared keyboard, wheel, pointer-drag, focus, reduced-motion, and spinbutton semantics already owned by `ScrollField`.

In 12-hour mode the hour wheel displays `1..12` and AM/PM remains a mutually exclusive radio group. Internally the public value is still normalized to `0..23`. In 24-hour mode the wheel exposes `00..23` and the AM/PM group is absent.

The wheel fields expose accessible value text such as the selected hour/period and minute value in addition to their numeric spinbutton state. Numeric time fields remain left-to-right inside an RTL page while the AM/PM control stays on the logical trailing side.

## Dial behavior

The active clock face uses slider-style semantics for hour or minute selection. Arrow keys adjust the active value; Enter/Space can advance the active selection according to the public interaction model. Pointer position maps to the corresponding hour/minute.

In 12-hour mode, AM/PM is a radio-group choice rather than a generic toggle. After an hour pointer selection completes, the picker advances to minute selection.

## Raw input drafts

`TimeInput` keeps native text-entry state separate from the last valid `TimeOfDay`. This matters while a user is partway through a value or has typed an out-of-range value: the application may need to observe or control the text exactly as entered without replacing the last valid time with an invalid model.

Use `draftValue` / `onDraftValueChange` for a controlled raw draft, or `defaultDraftValue` for an uncontrolled initial draft. The draft shape is intentionally web-native:

```ts
interface TimeInputDraftValue {
  hour: string;
  minute: string;
}
```

A valid draft updates `value`/`onChange`. An invalid draft remains visible and exposes `aria-invalid`, while `TimeOfDay` stays at its previous valid value. Blur does not silently conflate the invalid draft with that last valid time. Applications can choose when to reset, validate, submit, or replace the draft.

The string contract is deliberate: unlike an integer-only Kotlin state object, it can represent browser-native intermediate states such as an empty field.

## 12-hour and 24-hour presentation

Set `is24Hour` for `00..23` presentation and no AM/PM group. Without it, users interact with 12-hour values and AM/PM while the public `TimeOfDay.hour` remains normalized to `0..23`.

The same rule applies to dial, input, and scroll presentations.

## Expressive geometry

Current expressive picker geometry is compiled from canonical DTCG through the TimePicker Style Dictionary adapter. The vibrant time fields, 24-hour portrait width, separator, period selector, and related spacing therefore remain immutable Material facts in the token pipeline rather than per-render React style constants.

`variant="vibrant"` applies that expressive geometry to dial and input presentations. `TimeScroll` is the current vibrant scroll presentation by definition and does not add a redundant variant prop.

## Layout is component-local

`TimePicker.layout` accepts `vertical`, `horizontal`, or `auto`. `auto` observes the dial picker's **immediate container** and switches orientation at the audited picker threshold.

This is not Material window-size classification, does not consume `WindowAdaptiveInfo`, and does not participate in pane or navigation adaptation. `TimeInput` and `TimeScroll` keep their own presentation geometry instead of inheriting dial orientation switching.

## Accessibility

Keep hour/minute fields clearly named and preserve the radio semantics of AM/PM in 12-hour mode. Do not add application arrow-key or wheel handlers around `TimeScroll` that compete with the shared `ScrollField` interaction contract.

Invalid `TimeInput` drafts expose semantic invalid state while the valid value remains stable. When users need an explanation beyond invalid state, provide textual validation feedback; color or shape alone is not sufficient.

Large text/zoom must not reverse or overlap the hour/minute fields. Reduced-motion preferences remove ScrollField item transitions without changing the selected time model.

The reviewed Compose mapping includes `TimePicker`, `TimeInput`, `TimeScroll`, and the separation between valid `TimePickerState.hour/minute` and raw `hourInput/minuteInput`. Material supplies the presentation hierarchy, geometry, state intent, and selection behavior. Normalized React `TimeOfDay`, browser string drafts, native numeric text inputs, slider/radio/spinbutton semantics, shared `ScrollField` interaction ownership, and local ResizeObserver dial orientation are intentional web mappings.
