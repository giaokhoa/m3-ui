Snackbars show brief messages about an application process or result. `Snackbar` is the Material message surface; queueing, replacement, duration, persistence, and host policy remain application-owned.

```tsx
import {
  Snackbar,
  SnackbarAction,
  SnackbarDismissAction,
} from '@m3-ui/ui';

<Snackbar
  action={<SnackbarAction onPress={undo}>Undo</SnackbarAction>}
  dismissAction={
    <SnackbarDismissAction aria-label="Dismiss" onPress={dismiss}>
      <CloseIcon />
    </SnackbarDismissAction>
  }
>
  Message archived
</Snackbar>
```

## When to use

Use a snackbar for brief, non-blocking feedback that does not require the user to stop their current task. Use dialogs when a decision must be made before continuing, and use persistent inline status/error content when users must retain or revisit the information.

## Actions and layout

A snackbar can include one primary action and an optional dismiss affordance. `actionOnNewLine` selects the Material long-action composition when the action needs more room.

`SnackbarAction` reuses the Material text-button interaction engine. Icon-only dismiss actions require an accessible label because the icon is presentation-only.

## Lifecycle ownership

`Snackbar` deliberately does not create hidden timers, queues, replacement rules, or persistence. Application state or a dedicated host layer decides:

- when a snackbar appears;
- how long it remains;
- whether a new message replaces or queues behind the current one;
- how actions affect message state;
- whether state survives navigation or reload.

That keeps product policy outside the visual surface and avoids surprising timeouts embedded in a presentational component.

## Accessibility

The message is exposed as polite atomic status content so it can be announced without moving focus into the snackbar. Actions remain ordinary reachable controls.

Avoid rapidly replacing status text in a way that causes repeated announcements. A timeout should give users enough opportunity to perceive and operate any action, and product/accessibility policy should decide whether actionable snackbars require longer or user-controlled persistence.
