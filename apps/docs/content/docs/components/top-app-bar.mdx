Top app bars provide screen-level title, navigation, and action structure at the top edge of a composition. `TopAppBar` exposes the Material families through explicit variants and optional scroll state; it does not discover or subscribe to the page scroller itself.

[Material 3 top app bars](https://m3.material.io/components/top-app-bar/overview)

```tsx
import { TopAppBar } from '@m3-ui/ui';

<TopAppBar
  variant="large-flexible"
  title="Inbox"
  subtitle="12 unread"
  navigationIcon={<IconButton aria-label="Open navigation">...</IconButton>}
  actions={<IconButton aria-label="Search">...</IconButton>}
/>
```

## When to use

Use a top app bar for screen identity and high-level actions. Choose small/center-aligned/medium/large/flexible treatment from Material hierarchy and available screen composition rather than using title size as arbitrary decoration.

## Variants

The public family includes `small`, `center-aligned`, `medium`, `medium-flexible`, `large`, and `large-flexible`. Flexible medium/large variants can include a subtitle and transition an expanded title region toward the collapsed row.

## Scroll behavior is explicit state

`scrollFraction`, `overlappedFraction`, `state`, and `scrollBehavior` are explicit inputs. The component never installs a document scroll listener or assumes which nested/virtualized scroller should control it.

```tsx
const state = createTopAppBarState(
  collapsedFraction,
  contentOffset,
  overlappedFraction,
);
const behavior = TopAppBarDefaults.exitUntilCollapsedScrollBehavior(state);

<TopAppBar title="Inbox" variant="large" scrollBehavior={behavior} />
```

The surrounding scroll composition converts real scroll offsets into this public state. That keeps routing, scroll restoration, virtualized lists, and nested scrolling outside the visual primitive.

## Center-aligned local measurement

The center-aligned variant measures only its own navigation, action, and title slots to avoid overlap while maintaining visual centering. This is component-local geometry, not a window-size class or adaptive-layout rule.

## Accessibility

The root is a semantic header. Navigation and action slots contain independently named controls; the app bar is not one composite click target. Collapsed/expanded duplicate title presentation is managed so hidden duplicate content does not compete with the visible title.

## Material fidelity and web adaptation

<ParitySummary component="top-app-bar" />

Material supplies top-app-bar variants, hierarchy, collapse behavior, shape/color, and motion. Explicit React scroll state and local `ResizeObserver`-style measurement are web composition details; no hidden global scroll listener or adaptive breakpoint is added.
