Cards group related content and actions on a Material surface. Choose filled, elevated, or outlined treatment from the surrounding hierarchy; a card is not interactive by default.

[Material 3 cards](https://m3.material.io/components/cards/overview)

```tsx
import { Card, ElevatedCard, OutlinedCard } from '@m3-ui/ui';

<Card>Filled content</Card>
<ElevatedCard>Elevated content</ElevatedCard>
<OutlinedCard>Outlined content</OutlinedCard>
```

## When to use

Use cards to group content that benefits from a distinct Material container. Prefer ordinary document/layout structure when a separate surface does not add hierarchy. Keep cards passive when they contain independent links, buttons, fields, or other controls.

## Variants

`Card`, `ElevatedCard`, and `OutlinedCard` map to the three Material visual families. Canonical container colors, outlines, shapes, elevation, state layers, and elevation motion remain token-owned.

## Passive cards

Without `onPress`, a card is a non-interactive container. Put semantic content inside it normally and do not make it focusable merely to imitate an interactive visual state.

```tsx
<Card>
  <article>
    <h2>Release notes</h2>
    <p>Read what changed in this version.</p>
  </article>
</Card>
```

## Interactive cards

Supplying `onPress` opts into whole-card pointer/keyboard/focus state. The application must still choose semantics that match the action because a card can represent different domain behaviors.

```tsx
<OutlinedCard role="button" onPress={openDetails}>
  Open account details
</OutlinedCard>
```

For button-like cards, Enter/Space activation and disabled focus behavior are supported. If the intended action is document navigation, prefer a real link composition so browser link behavior is preserved.

## Nested interaction

Do not make a whole card interactive when it contains independent interactive descendants. A passive card containing explicit links/buttons gives each action a clear semantic owner and avoids nested-control conflicts.

## Accessibility

Material card appearance does not determine an accessible role. Static cards stay ordinary content containers. When `onPress` is used, supply the semantic role/name appropriate to the action and keep nested interactive controls out of the whole-card target.
