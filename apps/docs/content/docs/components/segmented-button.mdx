Segmented buttons group a small set of related choices in one connected Material surface. `m3-ui` exposes separate single-choice and multi-choice primitives so the visual family does not blur two different selection models.

[Material 3 segmented buttons](https://m3.material.io/components/segmented-buttons/overview)

```tsx
import {
  SingleChoiceSegmentedButton,
  SingleChoiceSegmentedButtonRow,
} from '@m3-ui/ui';

<SingleChoiceSegmentedButtonRow aria-label="Density" defaultValue="standard">
  <SingleChoiceSegmentedButton value="compact">Compact</SingleChoiceSegmentedButton>
  <SingleChoiceSegmentedButton value="standard">Standard</SingleChoiceSegmentedButton>
</SingleChoiceSegmentedButtonRow>
```

## When to use

Use segmented buttons for a small set of closely related choices that benefit from visible connected alternatives. Prefer radio buttons when the option set is larger or clearer as a conventional form group, and prefer checkboxes when independent choices do not need a connected segmented presentation.

## Single choice

`SingleChoiceSegmentedButtonRow` with `SingleChoiceSegmentedButton` uses one-of-many radio-group/radio semantics. Every segment has a `value`, and the group owns exactly one current selection.

```tsx
<SingleChoiceSegmentedButtonRow aria-label="View" defaultValue="list">
  <SingleChoiceSegmentedButton value="list">List</SingleChoiceSegmentedButton>
  <SingleChoiceSegmentedButton value="grid">Grid</SingleChoiceSegmentedButton>
</SingleChoiceSegmentedButtonRow>
```

## Multiple choice

`MultiChoiceSegmentedButtonRow` groups independent selectable segments. Each `MultiChoiceSegmentedButton` uses checkbox/toggle selection semantics so multiple segments can be active simultaneously.

```tsx
<MultiChoiceSegmentedButtonRow aria-label="Text formatting">
  <MultiChoiceSegmentedButton defaultSelected>Bold</MultiChoiceSegmentedButton>
  <MultiChoiceSegmentedButton>Italic</MultiChoiceSegmentedButton>
</MultiChoiceSegmentedButtonRow>
```

Do not describe multi-choice rows as a radio group or single-choice rows as independent toggles. Their browser semantics intentionally differ.

## Icons and selected state

Segments may provide an inactive `icon` and a `selectedIcon`. If no selected icon is supplied, the component can render the Material selected mark. Icons are presentation; the segment label and control semantics remain the accessible source of meaning.

Canonical outline, connected shape, spacing, state layers, typography, and selected/unselected colors come from component tokens rather than docs-owned CSS values.

## Accessibility

React Aria provides the appropriate radio or checkbox/toggle keyboard and selection behavior. Keep the row's accessible label meaningful and let the selected state communicate through the correct semantic model rather than adding custom key handlers.

Each segment should have a clear visible or accessible label. Do not rely on selected color or icon alone to convey the active choice.
