Text fields let users enter and edit text. Material 3 defines the filled and outlined visual families; `m3-ui` layers that presentation over native input/textarea behavior and React Aria field semantics.

[Material 3 text fields](https://m3.material.io/components/text-fields/overview)

<ComponentPreview>
  <TextField label="Name" isMultiline={false} />
  <OutlinedTextField label="Email" type="email" isMultiline={false} />
</ComponentPreview>

```tsx
import { TextField } from '@m3-ui/ui';

<TextField
  label="Email"
  name="email"
  type="email"
  autoComplete="email"
  isMultiline={false}
/>
```

## When to use

Use text fields for free-form text or structured values that benefit from direct keyboard entry. Choose filled or outlined presentation consistently within a form hierarchy instead of mixing variants arbitrarily.

Use picker/selection components when constrained choices are clearer than typing. Use `SecureTextField` only when masking/revealing a single-line value is appropriate; it is part of the text-field family, not a separate Material component family.

## Variants

| Public component | Material/web role |
| --- | --- |
| `TextField` | Filled text field |
| `OutlinedTextField` | Outlined text field |
| `SecureTextField` | Filled single-line secure field |
| `OutlinedSecureTextField` | Outlined single-line secure field |

`TextField` can also render multiline input through its public multiline/rows contract. Native browser attributes such as `type`, `name`, `autoComplete`, input mode, and refs remain available where applicable.

## Labels and supporting content

A visible `label` gives the field a stable identity. `supportingText` (or the documented `description` alias) adds guidance without replacing the label.

Prefix, suffix, leading-icon, and trailing-icon slots belong to the Material field composition. Do not use decorative slots as a substitute for a clear label.

## Validation and errors

Validation state is semantic, not only visual. Drive `isInvalid` and `errorMessage` from native constraints or application validation state.

<ComponentPreview>
  <OutlinedTextField
    label="Email"
    defaultValue="not-an-email"
    isInvalid
    errorMessage="Enter a valid email address"
    isMultiline={false}
  />
</ComponentPreview>

The component renders the Material error treatment and exposes the field/error relationship; it does not invent business validation rules. Cross-field, server, and workflow validation remain application-owned.

## Secure text fields

`SecureTextField` and `OutlinedSecureTextField` use the same field composition but always render a single-line native input. They default to password presentation and can expose a reveal action.

```tsx
<SecureTextField
  label="Password"
  name="password"
  autoComplete="current-password"
/>
```

Reveal state can be uncontrolled with `defaultRevealed` or controlled with `isRevealed` and `onRevealChange`. The reveal button uses pressed/toggle semantics and preserves input focus/selection where browser APIs allow.

Reveal changes presentation only. It does not store credentials, encrypt the value, choose password-strength rules, implement a password manager, or define an application's security policy.

## Behavior and states

React Aria owns field, label, description, error, input/textarea relationships and interaction behavior. The browser owns editing, selection, autocomplete, form participation, and native input capabilities. Material tokens own container, indicator/outline, typography, icon slots, state layers, and error presentation.

Disabled and read-only are different states: disabled controls are unavailable, while read-only values remain readable without permitting edits. Use the state that matches the actual workflow rather than a visual preference.

## Accessibility

Keep labels meaningful and expose errors as text. Use native attributes for browser-specific input requirements. Do not rely on placeholder text as the only label.

For secure fields, localize reveal/hide action labels when needed and keep them action-oriented. The reveal icon is not the accessible name; the toggle button's label and pressed state communicate the control.
