Menus present a temporary list of actions or choices anchored to a trigger. Material defines the visual menu surface and item anatomy; React Aria supplies the browser menu interaction model.

[Material 3 menus](https://m3.material.io/components/menus/overview)

<ComponentPreview>

</ComponentPreview>

```tsx
import { Button, Menu, MenuItem, MenuSection } from '@m3-ui/ui';

<Menu
  aria-label="Document actions"
  trigger={<Button>Actions</Button>}
  onAction={(key) => runAction(key)}
>
  <MenuSection label="Edit">
    <MenuItem id="rename">Rename</MenuItem>
    <MenuItem id="duplicate" supportingText="Create a copy">
      Duplicate
    </MenuItem>
  </MenuSection>
</Menu>
```

## When to use

Use a menu for a temporary list of actions or choices that should not occupy persistent screen space. Prefer visible buttons when actions are few and important enough to remain exposed. Use selection controls when choices should remain visible as form state.

## Anchored menu behavior

`placement`, `offset`, and `crossOffset` configure browser overlay positioning without redefining Material menu geometry. React Aria owns roving focus, Arrow/Home/End navigation, typeahead, Escape/outside dismissal, and focus restoration.

`MenuItem` keeps leading/supporting/trailing slots visual while the item itself remains the semantic action. Sections use real section/header relationships; visual section variants do not invent a new selection model.

## Selection and expressive groups

Set `selectionMode="single"` for one-of-many choices. React Aria exposes those items as `menuitemradio`; `selectedLeading` can swap the leading visual without changing the semantic label.

```tsx
<Menu
  aria-label="Text alignment"
  selectionMode="single"
  selectedKeys={selected}
  onSelectionChange={setSelected}
  trigger={<Button>Alignment</Button>}
>
  <MenuSection variant="segmented">
    <MenuItem id="left" leading="○" selectedLeading="✓">Left</MenuItem>
    <MenuItem id="center" leading="○" selectedLeading="✓">Center</MenuItem>
    <MenuItem id="right" leading="○" selectedLeading="✓">Right</MenuItem>
  </MenuSection>
</Menu>
```

Use `selectionMode="multiple"` for checkable choices; React Aria exposes them as `menuitemcheckbox`. `MenuSection variant="segmented" tone="vibrant"` applies the reviewed expressive group geometry and vibrant Material roles from generated canonical tokens.

For checkable menus that should remain open while several options are toggled, pass React Aria's `shouldCloseOnSelect={false}` through `Menu`.

## Cascading submenus

`MenuSubmenu` composes a Material submenu on React Aria `SubmenuTrigger`. Arrow-key direction, hover disclosure, Escape, focus travel, logical RTL behavior, collision handling, and nested overlay placement stay React Aria-owned.

```tsx
<Menu aria-label="Editor actions" trigger={<Button>Editor</Button>}>
  <MenuItem id="undo">Undo</MenuItem>
  <MenuSubmenu
    aria-label="Format options"
    trigger={<MenuItem id="format" trailing="›">Format</MenuItem>}
  >
    <MenuItem id="bold">Bold</MenuItem>
    <MenuItem id="italic">Italic</MenuItem>
  </MenuSubmenu>
</Menu>
```

Do not attach a competing Arrow/Escape handler to submenu triggers; the wrapper intentionally delegates that interaction model to React Aria.

## Exposed menu

`ExposedMenu` uses the Material text-field visual anchor for **read-only menu selection**.

```tsx
<ExposedMenu
  label="Density"
  value={densityLabel}
  onAction={(key) => selectDensity(key)}
>
  <MenuItem id="compact">Compact</MenuItem>
  <MenuItem id="standard">Standard</MenuItem>
</ExposedMenu>
```

The anchor communicates popup/expanded state and can open from pointer or keyboard activation. It is intentionally not an editable combobox or autocomplete. Do not describe users as typing into it or filtering options unless a separate editable public API is composed.

## Accessibility

Give menu triggers and menus meaningful names. Keep item labels usable for typeahead and accessible naming. Let the menu interaction model own arrow-key navigation and focus restoration rather than attaching competing keyboard handlers.

For `ExposedMenu`, preserve its read-only menu relationship; a text-field appearance does not make it a text input.
