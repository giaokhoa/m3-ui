Bottom app bars place important actions near the bottom edge of a screen composition. `BottomAppBar` provides the regular Material form and `FlexibleBottomAppBar` provides the expressive flexible arrangement; neither chooses responsive navigation policy on its own.

[Material 3 bottom app bars](https://m3.material.io/components/bottom-app-bar/overview)

```tsx
import { BottomAppBar, FloatingActionButton, IconButton } from '@m3-ui/ui';

<BottomAppBar
  actions={
    <>
      <IconButton aria-label="Search">...</IconButton>
      <IconButton aria-label="Edit">...</IconButton>
    </>
  }
  floatingActionButton={
    <FloatingActionButton aria-label="Create">...</FloatingActionButton>
  }
/>
```

## When to use

Use a bottom app bar when Material's bottom-edge action pattern fits the screen and the actions need persistent access. Adaptive selection between bottom app bars and other navigation/action surfaces belongs to the application layout/navigation owner, not this component.

## Regular and flexible composition

Actions remain independent controls with their own accessible names and state. An optional FAB is composed into the Material geometry without changing the FAB's semantics.

`FlexibleBottomAppBar` accepts an explicit local `horizontalArrangement` such as `space-between`, `fixed`, `start`, `center`, or `end`. This controls the row composition only; it is not a breakpoint API.

## Scroll behavior is explicit state

The exit-always behavior mirrors the audited Material/Compose state vocabulary:

```tsx
const state = BottomAppBarDefaults.createState(collapsedFraction, contentOffset);
const behavior = BottomAppBarDefaults.exitAlwaysScrollBehavior(state);

<BottomAppBar actions={actions} scrollBehavior={behavior} />
```

`collapsedFraction` can also be supplied directly. The component does not subscribe to page/document scrolling or decide which nested scroller drives the state. Applications own that integration and feed the result into the bar.

## Accessibility

Treat the app bar as a grouping surface, not a single action. Every action/FAB needs its own meaningful name, focus behavior, and pressed/selected state where applicable.

Do not hide an important action solely because the bar collapses unless the surrounding composition preserves an equivalent reachable control.
