Buttons let users trigger actions. Material 3 uses button variants to communicate action hierarchy; choose the variant from the importance and context of the action rather than styling every action independently.

[Material 3 buttons](https://m3.material.io/components/buttons/overview)

<ComponentPreview>
  <Button>Filled</Button>
  <ElevatedButton>Elevated</ElevatedButton>
  <FilledTonalButton>Filled tonal</FilledTonalButton>
  <OutlinedButton>Outlined</OutlinedButton>
  <TextButton>Text</TextButton>
</ComponentPreview>

```tsx
import { Button } from '@m3-ui/ui';

<Button onPress={save}>Save</Button>
```

## When to use

Use buttons for actions such as saving, confirming, creating, retrying, or opening an action flow. Use links for navigation to another document or URL. Prefer the dedicated `IconButton` family when the action is intentionally icon-only, and use FABs only for a screen-level high-priority action.

Keep one clear hierarchy within a surface. Multiple equally prominent filled buttons compete for attention and weaken the Material action structure.

## Variants

| Public component | Material role | Typical emphasis |
| --- | --- | --- |
| `Button` | Filled | Highest emphasis for a primary action |
| `ElevatedButton` | Elevated | High emphasis when separation from the surrounding surface is useful |
| `FilledTonalButton` | Filled tonal | Medium emphasis with a softer container |
| `OutlinedButton` | Outlined | Medium emphasis without a filled container |
| `TextButton` | Text | Lowest emphasis for supplementary actions |

Use the component family rather than reproducing Material container, state-layer, or elevation values in application CSS.

## Icons

`startIcon` and `endIcon` are decorative slots around the action label.

```tsx
<Button startIcon={<SaveIcon />}>Save</Button>
```

The component keeps these icon slots out of the accessibility tree so the visible action text remains the stable accessible name.

## Expressive sizes

The public `size` API exposes the audited Material expressive size vocabulary: `extraSmall`, `small`, `medium`, `large`, and `extraLarge`.

<ComponentPreview>
  <Button size="extraSmall">Extra small</Button>
  <Button size="small">Small</Button>
  <Button size="medium">Medium</Button>
  <Button size="large">Large</Button>
  <Button size="extraLarge">Extra large</Button>
</ComponentPreview>

Choose size from the surrounding component hierarchy and available touch target, not from arbitrary text length. Omitting `size` preserves the standard baseline behavior.

## Behavior and states

Material hover, focus, press, and disabled presentation is driven by real browser interaction state. React Aria owns the button interaction contract; canonical Material tokens, ripple, shape, color, elevation, and motion own presentation.

<ComponentPreview>
  <Button>Enabled</Button>
  <Button isDisabled>Disabled</Button>
  <OutlinedButton>Keyboard focusable</OutlinedButton>
</ComponentPreview>

Do not add independent click handlers to child content. The button is the single action owner.

## Accessibility

`Button` uses button semantics with keyboard activation, disabled handling, and focus-visible behavior supplied by React Aria. Prefer visible action text that describes the result of activation.

When an action must be icon-only, use an icon-button component and supply an accessible label. Do not remove button text visually while leaving an ambiguous accessible name.
