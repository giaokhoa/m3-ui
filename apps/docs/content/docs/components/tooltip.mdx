Tooltips provide contextual supporting information anchored to another control. Plain and rich Material tooltips share a visual family, but actionable rich content requires a different browser semantic model.

## When to use

Use a plain tooltip for short, supplemental text that clarifies an unfamiliar icon or control. Do not hide essential instructions only in hover content. Use a rich tooltip when the supporting content genuinely needs a title or action and should remain available long enough to interact with.

## Plain tooltip

`TooltipTrigger` + `PlainTooltip` follows the non-interactive tooltip pattern: trigger relationship, hover/focus timing, placement, portal behavior, and accessible description wiring are owned by React Aria.

```tsx
<TooltipTrigger>
  <Button>Info</Button>
  <PlainTooltip>Short supporting context</PlainTooltip>
</TooltipTrigger>
```

Keep plain tooltip content non-interactive. If users must move focus into the overlay, it is no longer a plain tooltip interaction.

## Rich tooltip

`RichTooltip` may contain an action, so exposing it as ARIA `tooltip` would be incorrect. It is built on React Aria `PreviewTrigger` + `Popover`: React Aria owns hover/focus timing, long press, safe-area pointer travel, Tab focus travel, popup relationships, Escape behavior, and non-modal dialog semantics.

```tsx
<RichTooltipTrigger>
  <Button>Shortcuts</Button>
  <RichTooltip
    title="Keyboard shortcuts"
    action={(close) => <TextButton onPress={close}>Got it</TextButton>}
  >
    Press Command K to open search.
  </RichTooltip>
</RichTooltipTrigger>
```

Focus may move into the rich action without modal focus containment. Escape returns focus to the trigger and touch users can open the preview with a long press. `isPersistent` defaults to `true` for Material rich tooltips. React Aria does not expose an equivalent persistent-preview option, and PreviewTrigger intentionally uses a non-dismissable non-modal Popover, so m3-ui retains a small close-filter adapter plus React Aria `useInteractOutside` for Material's outside-dismiss behavior. No document-level pointer listener is implemented by m3-ui.

## Caret

Both `PlainTooltip` and `RichTooltip` accept an opt-in `caret` prop. It is off by default, matching the reviewed Compose API where the caret shape is nullable.

```tsx
<TooltipTrigger>
  <Button>Info</Button>
  <PlainTooltip caret placement="top">
    Supporting context
  </PlainTooltip>
</TooltipTrigger>
```

The default Material caret is 16×8 px and inherits the tooltip container color. It is rendered through React Aria `OverlayArrow`, so React Aria owns arrow coordinates, collision flips, and resolved placement while Material supplies only triangle geometry and paint. Logical `start`/`end` placement follows React Aria locale direction; the explicit per-component `dir` override is adapted for compatibility because RAC positioning reads locale direction rather than the local DOM attribute.

## Portals and theme context

Tooltip surfaces are portalled. Public theme variables are projected into the portal so nested Material themes remain visually coherent without leaking component-private implementation variables.

## Accessibility

Ensure the trigger is reachable without hover and that plain tooltip text remains concise. Do not place links/buttons inside `PlainTooltip`.

For rich tooltips, provide enough title/content to identify the non-modal dialog-like surface and keep actions keyboard reachable. Avoid treating an actionable overlay as `role="tooltip"`, which does not support interactive descendants as a user interaction model.
