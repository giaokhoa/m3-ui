Dividers separate related content regions when a visible boundary improves structure. Material defines the visual treatment; on the web, `m3-ui` exposes real separator semantics rather than using a decorative line with no relationship to content.

[Material 3 dividers](https://m3.material.io/components/divider/overview)

## When to use

Use a divider when the boundary between adjacent groups is meaningful and should be perceivable beyond spacing alone. Prefer layout spacing when you only need visual breathing room.

Do not insert semantic separators merely to imitate margins or padding; unnecessary separator roles add noise for assistive technology.

## Orientation

`HorizontalDivider` and `VerticalDivider` expose their orientation directly. Each renders separator semantics with the matching orientation instead of guessing from surrounding CSS.

Use the horizontal form between vertically stacked regions and the vertical form between horizontally arranged regions when that separation is meaningful.

## Material defaults and overrides

Default color and thickness come from the audited Material divider/token contract. `color` and `thickness` are explicit web customization hooks for deliberate composition changes.

```tsx
<HorizontalDivider thickness="2px" />
```

An override does not create a new canonical Material token. Reusable design decisions belong in the token/theme system instead of being copied across application CSS.

## Accessibility

The divider is a separator, not interactive content. It should not receive focus or click behavior. Use it only when the semantic region boundary is useful; use spacing for decoration-only separation.
