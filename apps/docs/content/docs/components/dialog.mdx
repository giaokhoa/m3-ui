## Overview

Dialogs interrupt the current flow to present focused information or request a decision. Use them for short, high-priority interactions that benefit from modal attention rather than as a general-purpose page container.

<ComponentPreview>
  <DialogTrigger>
    <Button>Open dialog</Button>
    <DialogOverlay>
      <Dialog>
        <DialogTitle>Delete item?</DialogTitle>
        <DialogDescription>
          This action cannot be undone.
        </DialogDescription>
        <DialogActions>
          <DialogCloseAction>Cancel</DialogCloseAction>
          <DialogCloseAction>Delete</DialogCloseAction>
        </DialogActions>
      </Dialog>
    </DialogOverlay>
  </DialogTrigger>
</ComponentPreview>

## Composition

The React API is intentionally decomposed so Material presentation and browser modal behavior remain explicit.

| Primitive | Responsibility |
| --- | --- |
| `DialogTrigger` | Trigger state and focus restoration |
| `DialogOverlay` | Modal underlay, Material scrim, dismissal, and portal placement |
| `Dialog` | Material container surface and dialog semantics |
| `DialogIcon` | Optional leading dialog icon region |
| `DialogTitle` | Accessible headline |
| `DialogDescription` | Supporting text associated with the dialog |
| `DialogActions` | Material action row |
| `DialogAction` | Material text action without implicit close behavior |
| `DialogCloseAction` | Material text action wired to React Aria's close slot |

## Actions

Keep the action set concise and directly related to the decision in the dialog. `DialogAction` reuses the Material text-button interaction engine with dialog action token roles. `DialogCloseAction` adds the close behavior without duplicating modal state.

```tsx
<DialogActions>
  <DialogCloseAction>Cancel</DialogCloseAction>
  <DialogAction onPress={save}>Save</DialogAction>
</DialogActions>
```

## Dismissal

`DialogOverlay` is dismissable by default. React Aria owns outside dismissal and Escape behavior. Set `isDismissable={false}` only when the interaction genuinely must block dismissal and provide an explicit action path.

## Theme portals

Dialogs render through the theme-aware portal container created by `ThemeProvider`. This keeps Material color variables and theme state available even though the modal is portaled outside the local DOM subtree.

## Accessibility

React Aria owns modal focus containment, accessible dialog relationships, focus restoration, Escape handling, and portal behavior. Use `DialogTitle` and `DialogDescription` so the modal has a clear accessible name and supporting description.

## Web adaptation

The web implementation does not recreate Compose dialog runtime mechanics. The Material surface, scrim, typography, colors, shape, and action styling are layered on React Aria's browser modal model. The underlay remains the single interactive backdrop while the Material scrim is presentation-only.
