Dialogs interrupt the current flow to present focused information or request a decision. Use them for short, high-priority interactions that benefit from modal attention rather than as general page containers.

[Material 3 dialogs](https://m3.material.io/components/dialogs/overview)

## When to use

Use a dialog when users must focus on a concise decision, confirmation, or short task before returning to the underlying flow. Prefer inline content, sheets, or full pages for longer tasks that do not need modal interruption.

## Composition

The public primitives keep Material presentation and browser modal responsibilities explicit:

- `DialogTrigger` owns trigger/open state and focus restoration;
- `DialogOverlay` owns portal placement, modal underlay, Material scrim, outside/Escape dismissal policy, and browser focus containment;
- `Dialog` owns the Material container and dialog semantics;
- title/description/icon/action primitives compose the Material content hierarchy.

## Actions

Keep action sets concise and directly related to the dialog decision. `DialogAction` performs an action without implicit close behavior; `DialogCloseAction` uses the close slot when activation should dismiss the dialog.

```tsx
<DialogActions>
  <DialogCloseAction>Cancel</DialogCloseAction>
  <DialogAction onPress={save}>Save</DialogAction>
</DialogActions>
```

## Dismissal and modal behavior

`DialogOverlay` is dismissable by default. React Aria owns Escape/outside dismissal, modal focus containment, scroll interaction policy, and focus restoration. Set non-dismissable behavior only when the task genuinely requires an explicit action path.

The Material scrim is presentation inside the overlay contract. It is not a second modal/focus manager.

## Accessibility

Use `DialogTitle` and, when useful, `DialogDescription` so the dialog has a clear accessible name and supporting relationship. Keep focusable content purposeful and ensure a non-dismissable dialog always offers a reachable way to complete or cancel the task.

Do not manually add a second focus trap or Escape handler around `DialogOverlay`; competing modal managers can break restoration and keyboard interaction.
