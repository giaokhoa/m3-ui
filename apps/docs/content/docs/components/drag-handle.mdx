`VerticalDragHandle` renders the Material resize affordance and its interaction-state presentation. It is intentionally not a complete splitter, pane controller, or drag state machine.

</ComponentPreview>

```tsx
import { VerticalDragHandle } from '@m3-ui/ui';

<VerticalDragHandle
  isDragged={isResizing}
  role="separator"
  aria-label="Resize panes"
  aria-orientation="vertical"
/>
```

## When to use

Use the handle as the visual/interaction affordance for an owner that already knows how a split or pane can resize. Prefer the higher-level pane/scaffold resize APIs when they already provide the state/constraints required by the application.

## Controlled dragged state

`isDragged` selects the Material dragged-state shape/color while pointer press feedback remains local to the handle. The owner decides when a resize session starts/ends and updates the actual split position.

Do not infer pane width, drag limits, or application layout policy from the handle itself.

## Accessible resizing contract

When the handle is an adjustable separator, the resize owner should provide semantics describing the real control: separator role, orientation, accessible name, value range/current value when meaningful, and keyboard resizing that updates the same state as pointer dragging.

The primitive forwards DOM props so this contract can be supplied without inventing a second state model inside the visual handle.

## Layout boundary

A handle may resize a local split or participate in an adaptive scaffold, but `VerticalDragHandle` itself does not calculate pane directives, window classes, anchors, or constraints. Those belong to the component that owns the resize model.

## Accessibility

A decorative handle that cannot be operated should not pretend to be an adjustable separator. An operable handle needs a non-pointer path—typically keyboard adjustment—and current/range semantics when the split has a meaningful numeric position.

Keep `isDragged` as visual feedback, not the only communicated state of an adjustable control.

## Material fidelity and web adaptation

Material supplies the handle geometry, shape, color, minimum interaction target, and dragged/pressed/focus visuals. Resize semantics, keyboard changes, pointer coordinates, constraints, and pane/layout state remain the owner's web/application responsibilities.
