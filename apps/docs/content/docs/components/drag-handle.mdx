## Overview

`VerticalDragHandle` renders the Material resize affordance and its default, pressed, hover, focus, and dragged visual states. It is intentionally **not** a complete resize widget.

<ComponentPreview>
  <VerticalDragHandlePreview />
</ComponentPreview>

The preview toggles `isDragged` explicitly. A real pane or splitter owner should set that value from its actual drag lifecycle.

## Controlled drag state

`isDragged` changes the handle's Material dragged-state shape and color. Pointer press feedback is internal, but moving a pane or changing a split position remains outside this primitive.

```tsx
<VerticalDragHandle
  isDragged={isResizing}
  role="separator"
  aria-label="Resize panes"
  aria-orientation="vertical"
/>
```

## Accessible resizing

When the handle represents an adjustable separator, the owner should provide the semantics that describe its actual resize model. That commonly includes:

- `role="separator"`
- an accessible name
- `aria-orientation="vertical"`
- `aria-valuemin`, `aria-valuemax`, and `aria-valuenow` when the split has a numeric range
- keyboard resizing such as Arrow keys
- pointer movement that updates the same underlying split state

The primitive forwards DOM props so the resize owner can provide this contract without the visual component inventing a second state model.

## Why drag logic is external

A drag handle can resize a pane, adjust a local split, or participate in a higher-level adaptive scaffold. Those owners have different constraints and state lifecycles. `VerticalDragHandle` therefore owns only Material interaction feedback and appearance; it does not define pane directives, window-size classes, or layout policy.
