## Material 3 is the contract

The documentation surface uses the same `@m3-ui/ui` components, theme roles, and generated typography tokens as consumer applications. Fumadocs provides the content pipeline; it does not define the visual language.

## Headless documentation engine

`fumadocs-mdx` compiles the MDX source and provides browser-safe Macro collections. This app intentionally does not import `fumadocs-ui`, its preset CSS, or a parallel design system.

```tsx
const page = getDocsPage(slugs);
const MDX = page.body;

<MDX components={getMdxComponents()} />;
```

## Layout boundary

> Documentation owns content composition, not Material adaptive-layout policy.

The docs app does not define its own compact, medium, or expanded breakpoints; pane directives; navigation rail switching; or scaffold algorithms. Those concerns must compose the existing `@m3-ui/ui/layout` subsystem as that work lands.

## Typography boundary

Semantic Markdown remains semantic HTML. Headings and body content are mapped to Material type roles at the MDX boundary instead of introducing documentation-only typography components into the core library.
